# 需求说明（题目02：宠物门店预约经营）

> 填写要求：每条规则都必须能落到“可观察、可断言”的验收条件；与题面冲突时以题面为准。

## 1. 角色与诉求

| 角色 | 主要诉求 | 关键操作 | 失败/异常诉求 |
|---|---|---|---|
| 店长 | 知道每个时段来多少宠物、一天收了多少、退了多少 | 发布时段、日清、标记未到店 | 名额错乱、金额对不上 |
| 宠物主人 | 约得上、付得清、取消有明确结果、看得到服务结果 | 预约、支付、取消、查询 | 名额被占、退款失败要能用 |
| 前台 | 到店快速核验且不能误放 | 核销 | 待审取消/已取消/跨店要明确拒绝 |
| 服务人员 | 登记开始/完成，不重复记收入 | 开始、完成 | 未核销不能开始 |
| 客服 | 按环节处理取消与退款失败 | 审核、重试退款 | 退款失败不能让预约复活 |
| 模拟渠道 | 可控地返回成功/失败/超时/重复通知 | 支付/退款回调 | 重复与迟到通知可验证 |

## 2. 主流程（文字 + 状态）

```
店长发布时段 → 用户选择宠物预约（占名额 5 分钟）→ 支付成功（已确认）
→ 前台核销（已到店）→ 服务人员开始（服务中）→ 完成（已完成）
→ 用户查看结果 / 店长日清核查
分支：超时释放、未付款取消、≥2h 取消自动退款、<2h 取消客服审核、
      退款失败重试、未到店标记、关闭后支付异常退款、取消与核销并发
```

## 4. 边界与异常清单

- 时段：未开始/刚好开始；容量 0/满/释放后；同一宠物同时段重复；跨店操作。
- 时间：4m59s vs 5m；`start_at-2h` 边界；时段结束边界。
- 支付：成功、失败、超时、重复通知、关闭后通知、金额不一致、签名缺失。
- 取消：未付款取消、≥2h、<2h 有/无原因、待审核销、批准、拒绝、重复批准。
- 服务：重复核销、跳步开始、重复完成、完成后再取消。
- 退款：成功、失败、超时、重试成功/再次失败、金额不符、失败后预约是否恢复（必须否）。
- 日清：同在一天出现四类记录；金额四口径对账。

## 5. 不做范围

优惠券、会员积分、排班优化、多店结算、真实短信、注册登录全套、档案编辑、争议退款裁决、真实支付接入。
