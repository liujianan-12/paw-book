# 10 过程证据与 AI 使用记录

题目要求：导出从需求分析到上线验收的**全部可见会话**，按阶段保留时间顺序；提交 Markdown 会话导出 + 按时间排序的结构化事件清单（JSON/JSONL）；无法导出的平台内容列出缺失范围；无需隐藏指令/隐藏推理。另交一页 AI 使用说明与视频时间点目录。

## 1. 目录结构

```
docs/sessions/
  01-需求分析.md
  02-原型设计.md
  03-任务规划.md
  04-开发-dev.md
  05-测试-test.md
  06-验收-acceptance.md
  07-修复返工.md
  08-部署与合并.md
  events.jsonl                  # 结构化事件，按时间排序
docs/ai-usage.md                # 一页 AI 使用说明
docs/evidence/ai/
  prompts-index.md              # 提示词清单（阶段、意图、所在会话行号）
  missing-scope.md              # 无法导出的平台/范围说明
  redaction.md                  # 脱敏说明（哪些字段被替换）
```

## 2. 会话导出格式（Markdown）

每个阶段文件按时间顺序记录：

```markdown
## <时间戳> <角色>（学生/Agent）
> 工具：<工具名> ｜ 模型：<可获取则写，否则“不可获取”> ｜ 关联任务：T4.2 ｜ 代码版本：<sha>

**学生输入**：<完整提示词/补充上下文>
**Agent 可见回复**：<完整回复或关键结论+全文附件路径>
**工具调用**：<命令/参数/输出摘要/失败与重试>
**产出**：<文件路径、提交 SHA>
```

- 不得只截取“成功部分”；失败、重试、纠错必须保留。
- 截图/原型/附件用相对路径索引，不内嵌大图。

## 3. events.jsonl 字段（固定 schema）

```json
{"ts":"2026-11-12T09:12:03+08:00","stage":"requirements","actor":"student","tool":"agent","session":"01","model":"不可获取","taskId":"T1","action":"prompt","input":"...","outputSummary":"...","result":"ok","artifacts":["docs/requirements.md"],"commit":null}
{"ts":"...","stage":"dev","actor":"agent","tool":"bash","command":"go test ./...","result":"fail","exitCode":1,"artifact":"docs/evidence/tests/abc/test-output.txt","commit":"abc123"}
```

要求：时间升序；每条含阶段、执行者、工具、动作、结果、证据路径；`result` 只能是 `ok/fail/blocked`；失败必须有后续修复事件可对应。

## 4. AI 使用说明（一页，模板）

| 阶段 | AI 完成 | 学生完成 | 学生审核内容 | 有依据的纠错 |
|---|---|---|---|---|
| 需求分析 | 草拟角色/规则表 | 逐条对照题面修订、定假设 | 规则编号与题面映射 | 指出 AI 漏了“关闭后支付不恢复预约”，补入 R2.6 |
| 原型 | 生成页面骨架 | 调整角色操作与异常展示 | 是否覆盖四角色 | — |
| 开发 | 生成实现与测试 | 审核事务/锁/状态迁移、改写错误码 | diff 逐段 | 修复 AI 先查后改的并发缺陷（提交 x） |
| 测试/验收 | 执行检查、汇总 | 独立判断、复核证据 | 报告与原始输出是否一致 | — |

> 不得用“提示词数量”“自报生成比例”代替过程证据；不得编造纠错。

## 5. 脱敏规则（强制）

- 删除/替换：真实手机号、身份证、邮箱、地址、密码、token、DSN、内网/公网 IP、仓库密钥、GitHub Secrets、教师环境凭据。
- 演示数据统一用合成姓名/宠物名/尾号 0000 的手机号。
- 脱敏只改值不改结构；`docs/evidence/ai/redaction.md` 列出脱敏字段与方式。
- 视频中若出现终端，需先确认无敏感信息；必要时裁剪。

## 6. 视频（可录 1 个连续或 2 个关联视频）

必须由学生本人讲解，按思路串起：来源岗位与改编 → 业务背景/角色/规则/分支 → 需求理解 → 原型如何服务角色 → 任务为何这样拆 → Agent 如何开发、学生如何审核 → 如何测试与处理缺陷 → 如何独立验收 → 如何合并与自动部署 → 展示 Agent 约束与 Skill 实际使用（指向证据）→ 完整多角色效果演示（S1–S5 + 关键异常）→ 模拟依赖说明 → 质量证据（覆盖率、race、缺陷、部署版本）。
