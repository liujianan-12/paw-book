# 02 原型说明

原型文件：`prototype/index.html`（纯静态 HTML，双击浏览器打开即可点击）
性质：**设计沟通用的静态原型**，按钮只做页面状态切换与提示，不接真实业务；真实系统在开发阶段实现，业务规则以 `docs/01-需求说明.md` 为准。

## 页面清单与状态说明

### 宠物主人（4 个页面 + 2 个弹层）
| 页面 | 主要操作 | 展示的状态/异常 |
|---|---|---|
| 时段列表 | 预约 | 满/已开始按钮禁用并说明原因 |
| 预约弹窗 | 选自己的宠物提交 | 同宠物同时段唯一、未付款占名额 5 分钟提示 |
| 待支付页 | 支付 / 取消 | 5 分钟倒计时；支付成功/失败重试/超时取消三分支；已关闭预约收到付款 → 异常登记+退款提示 |
| 取消弹窗 | 填原因提交 | ≥2h 直接受理退款；<2h 进入取消审核中（名额保留、禁止核销） |
| 我的预约列表 | 查看结果/取消 | 全状态徽章：待支付、已确认、审核中、已核销、已完成、已取消(退款失败)、未到店 |

### 前台（1 个页面）
- 今日本店预约列表；核销按钮仅对"已确认 + 无待审核取消"可用。
- 校验三条件演示：本店员工 / 已确认 / 无待处理取消申请。
- 异常提示：审核中不可核销、重复核销拒绝、取消与核销并发的唯一合法结果、非本店员工拒绝。

### 客服（2 个页面）
- 取消审核：批准 → 已取消+退款+释放名额；拒绝 → 恢复已确认。
- 退款跟进：退款失败记录可重试；强调退款失败不影响取消结果。

### 店长（3 个页面）
- 发布时段：起止时间必填，容量固定 3。
- 标记未到店：时段结束后可操作，须填原因；本题约定不自动退款。
- 日清看板：各状态数量统计 + 金额勾稽（已收款 = 已完成收入 + 已退款 + 未退款）+ 当日明细表（区分"计入收入"与"不计收入"）。

## 与验收场景（S1–S5）的对应

| 场景 | 原型体现 |
|---|---|
| S1 正常接待 | 主人 1→2→3 页 + 前台核销 + 店长日清明细第一行 |
| S2 名额循环 | 主人页 1 的"剩 2 位/已满" + 待支付倒计时超时取消 |
| S3 取消分支 | 主人取消弹窗两分支 + 客服两页 |
| S4 现场冲突 | 前台页的并发冲突提示与禁用按钮 |
| S5 收店核查 | 店长日清看板五种状态 + 金额勾稽 |

## 说明
- 原型不实现登录，真实系统按角色预置账号登录（见需求说明 7.技术边界）。
- 时间规则（2 小时 / 5 分钟）在真实系统中可配置缩短以便演示。
