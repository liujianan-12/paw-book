# gofmt 门禁的 CRLF 修复记录（2026-11-12）

## 现象

本机 `gofmt -l .` 列出 44 个 `.go` 文件，而独立验收报告记录为「空输出」，看似门禁不一致。

## 真实诊断输出

```
git config --get core.autocrlf        → true
git ls-files --eol cmd/server/main.go → i/lf    w/crlf    attr/
git ls-files --eol internal/api/server.go → i/lf    w/crlf  attr/
.gitattributes                        → (none)
gofmt -d cmd/server/main.go           → 整文件替换，内容仅为 CRLF→LF，无格式/代码差异
worktreeCRLF=True
```

结论：仓库（index）存的是 **LF**，Windows 检出被 `core.autocrlf=true` 转成 **CRLF**，Go 的 `gofmt` 期望 LF，因此把文件判为「需格式化」。这是**换行符假阳性**，不是代码格式问题；Linux 的 CI checkout 为 LF，不受影响。

## 处理（不改业务代码、不改 git config）

1. 新增 `.gitattributes`：`*.go text eol=lf`，固定后续检出使用 LF。
2. 把工作区 44 个 `.go` 文件的 CRLF 转为 LF（仅替换换行符，UTF-8 无 BOM；`bomSkipped=0`）。
3. `git add --renormalize -- '*.go'` 刷新 index 的 stat 缓存。

## 验证

```
goFiles=44 converted=44 bomSkipped=0
gofmt -l .                 → gofmtListed=0
git diff --numstat -- '*.go' → goDiffFiles=0
git diff --cached --name-only -- '*.go' → stagedGoFiles=0
go vet ./...               → exit 0
go test ./... -count=1     → exit 0（api/domain/paychannel/payclient/repo/service 全 ok）
```

`git status` 中 44 个 `.go` 的 `M` 是 stat 缓存导致的假差异，renormalize 后已消失；**暂存区与提交中没有任何 Go 代码内容改动**。

## 口径

- 不修改 `git config`（按工具安全约束），改用仓库内 `.gitattributes` 解决。
- 本次只修换行符，未 `gofmt -w` 重写代码、未改任何业务行为。
- 该记录不构成 `-race` 证据；`-race` 仍 BLOCKED，见 `docs/evidence/git/race-attempt-2026-11-12.md`。
